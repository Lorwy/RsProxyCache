# 在 Android 和 iOS App 内运行代理

移动端采用内嵌代理，代理在宿主 App 内运行，视频字节缓存在设备上。Android 和 iOS 首版仅支持通过 HTTP Range 读取的单文件 MP4。

宿主 App 将源地址交给内嵌代理，再将返回的回环代理播放地址交给播放器。播放器通过 HTTP Range 读取视频，同一 App 进程内的播放器共享一个由宿主按需启动和关闭的代理实例。关闭单个播放器时，其余播放器的请求可以继续。

宿主配置 App 私有缓存目录和容量上限。缓存仍在磁盘上时可以跨 App 重启复用，被系统清理后再按需回源。首版提供按需播放缓存，离线下载作为独立能力。

代理每次启动时分配临时回环端口，只接受当前实例签发的代理播放地址，并沿用源站白名单。实例重启后，宿主使用源地址取得新的代理播放地址。

首版播放验收覆盖前台播放和回到前台后的恢复。后台持续播放、锁屏播放和画中画留待后续。磁盘不可用时，代理尽量继续回源播放。代理启动失败或失效时，SDK 将错误交给宿主处理，由宿主决定如何重试、降级或提示失败。

Android 首版交付可由 Kotlin 调用的 AAR，以 Media3 ExoPlayer 验收起播、跳转和重启 App 后的缓存复用。iOS 首版交付包含真机和模拟器 Framework 的 XCFramework，交付检查覆盖 Swift 工程的导入与链接。iOS 播放器联调与播放验收留待后续。

首版 SDK 暴露启动、获取代理播放地址和关闭三个操作。宿主启动时提供缓存目录、容量上限和源站白名单，启动成功后传入 MP4 源地址获取代理播放地址。回源支持公开 URL 和自带签名的 URL。缓存管理、预下载和自定义回源鉴权头留待后续。
