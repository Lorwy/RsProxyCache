# HLS 点播沿用代理播放入口并按需缓存媒体数据

独立服务及 Android、iOS 内嵌代理共用 HLS 点播能力，沿用现有代理播放地址约定和 SDK API。入口可由 `.m3u8` 路径后缀或源站响应的 HLS 内容类型识别。支持主播放列表和媒体播放列表、多码率、独立音轨和字幕、MPEG-TS、fMP4、字节范围分片、明文和通过 HTTP(S) 获取密钥的标准 AES-128。直播、低延迟直播、SAMPLE-AES 和 DRM 留待后续。

代理以重定向后的最终源地址解析播放列表中的相对 URI，将引用改写为代理播放地址，并保留源地址自带的查询串。内嵌代理按实例为每个子资源签名。子资源和重定向目标沿用现有回源白名单。

播放列表每次请求都回源并改写，避免重复使用含过期签名的引用。AES-128 密钥每次按需回源，由播放器解密。完整媒体分片、初始化数据和字节范围分片按完整源地址持久化，与单文件视频共享磁盘容量和全局 LRU。重复播放可复用媒体数据，仍需取得播放列表和所需密钥。分片源地址的签名变化会产生新的缓存项。

媒体播放列表必须包含 `EXT-X-ENDLIST`。遇到不支持的加密方式或无法安全代理的引用时，拒绝返回当前播放列表。主播放列表引用的子列表在播放器请求时逐个处理。

自动化验收覆盖主列表和子列表改写、重定向后的相对 URI 解析、签名查询串保留、MPEG-TS 和 fMP4、字节范围分片、AES-128 密钥回源、回源白名单拒绝以及重启后媒体缓存命中。Android 使用 Media3 真机验收起播、跳转、多码率切换、音轨和字幕选择，以及重启 App 后的分片复用。iOS 验收覆盖 XCFramework 构建和 Swift 链接，真实播放留待后续。
