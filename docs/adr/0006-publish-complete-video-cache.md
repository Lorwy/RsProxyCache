# 完整缓存按源地址路径发布

完整的单文件视频缓存以原文件名原子发布，优先使用源地址的 `host/path` 布局。完整源地址仍用于区分缓存条目，路径冲突时在扩展名前加稳定短后缀，文件名不包含原始查询串。发布前继续复用已缓存区间。

已发布的 HLS 点播以本地 `m3u8` 为入口，其中的相对路径指向本地播放所需资源，播放器可以脱离代理和源站直接打开。

普通播放按需缓存，收齐后自动发布。显式的离线缓存操作负责主动补齐。HLS 媒体播放列表须收齐全部分片及播放依赖。主播放列表在至少一个清晰度及其播放依赖齐全后即可发布，本地列表只引用已完整缓存的选项。

首版只发布明文 HLS。AES-128 HLS 继续支持在线播放和媒体数据缓存，密钥按需回源。显式离线缓存遇到 AES-128 时返回明确的暂不支持状态。

Android、iOS SDK 和独立服务提供显式离线缓存入口，支持查看进度和取消。同一完整源地址和清晰度的并发请求共享任务及进度。正在下载时收到同一源地址的其他清晰度请求，返回正在下载及当前清晰度，由调用方决定等待或取消。补齐新清晰度期间，已发布的清晰度仍可离线播放。取消后保留仍可复用的区间和分片。HLS 下载支持指定清晰度，缺省时补齐最近播放的清晰度，首次播放前选择带宽最低的可播放版本。首版主动补齐所选版本及默认音轨，其他音轨和字幕在实际播放并缓存完整后可加入本地播放列表。

相同完整源地址命中已发布缓存时，原代理播放地址直接从本地提供内容，签名过期或源站不可达时仍可播放。跨域 HLS 资源各自按源地址的 `host/path` 落盘，本地播放列表用相对路径引用。整体移动缓存目录时保留资源之间的相对位置。

HLS 字节范围资源已缓存整个源文件时，保留原文件和播放列表中的字节范围引用。只收齐播放所需区间时，将各区间发布为同目录下带范围后缀的独立资源，按各文件内的实际偏移更新本地播放列表。原文件名留给完整源文件。

已发布缓存继续计入全局缓存容量。单文件视频按整文件回收，HLS 按可播放条目撤下入口，共享资源保留到没有其他已发布条目引用时。

按完整源地址主动清理 HLS 播放入口时，先撤下入口，再释放其独占的子列表、分片和初始化数据。直接清理共享资源时，先撤下依赖它的所有播放入口。需要刷新同一源地址下的已发布内容时，调用方先清理再重新发起播放或缓存。补齐尚未发布的资源时，跨响应合并字节仍须满足 ADR 0003 的强 `ETag` 一致性要求。

常规 URL 路径原样保留。遇到文件与目录同名、文件系统字符限制等情况时，使用确定性的转义或后缀。保留已有扩展名，仅在缺少扩展名且媒体类型明确时补全。未完成的区间、索引和任务状态放在缓存根目录的保留子目录中。HLS 的依赖文件可以先落盘，播放列表在所引用的资源齐全后发布。

用户可以复制已发布缓存。代理发现文件丢失或被替换时，将对应条目标记为失效并撤下受影响的 HLS 入口。后续播放或离线缓存请求按需回源补齐。

离线缓存任务随进程结束。再次发起时复用仍有效的缓存数据，移动端首版以 App 运行期间的显式下载为主。任务运行期间保护其仍需使用的数据，并遵守全局容量上限。确定无法在上限内完成时返回容量不足，任务结束后已下载数据恢复参与普通淘汰。

项目尚未正式发布，新布局直接替换旧布局，移除旧落盘格式的读写和迁移路径。

本决策扩展 ADR 0003 的区间缓存布局和 ADR 0005 的 HLS 分片复用模型，使人可以从缓存目录直接找到并打开完整视频。
