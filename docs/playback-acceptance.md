# 首版播放验收

使用可控测试源站记录每次回源的请求范围、次数和响应体字节数。

- 清空缓存后，直接请求单文件视频中间的字节区间，验证服务按需回源并返回正确的 `206` 和字节内容。部分命中时，记录的回源响应体字节数应等于缺口大小。
- 重复请求同一区间，验证回源次数保持不变。重启代理后再次请求，验证仍然命中。
- 在同一源地址替换视频并更新强 `ETag`，构造需要补齐缺口的请求，验证响应只包含新版本字节。模拟检测到换片之后的重取失败，验证后续请求不会继续命中已失效的旧区间。
- 并发发送两个范围不同的播放请求，使它们共享同一缺口，验证缺口只回源一次。
- 调小容量上限，访问多个区间后触发淘汰，验证优先腾出最久未使用区间占用的空间。

使用至少一个实际要接入的播放器，打开直接拼接的 `/v1/https://…` 地址，验证能起播并拖动进度条。检查代理收到的路径和查询串，确认双斜杠、签名参数顺序和百分号编码得到保留。目标播放器在实际接入时确定。
