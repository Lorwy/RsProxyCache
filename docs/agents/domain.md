# Domain docs

This repository uses a single-context layout with `GLOSSARY.md` at the root and ADRs under `docs/adr/`.

Before exploring the codebase, read the glossary and ADRs relevant to the task when they exist. Continue silently if they are absent. Use `domain-modeling` to record terms and decisions as they are settled.

Use glossary terms in issues, proposals, and test names. If a term is missing, check existing project terminology and flag any gap for `domain-modeling`. If a proposal conflicts with an ADR, identify the ADR and explain why the decision should be revisited.
